# 接收与失败处置手册

## 运行前

只处理自己拥有或明确获授权的本地包。生产入口并未实现；接收真实数据前应配置可信身份、单用户/全局任务额度、速率限制、独立低权限 worker 与资源配额。工作区不在 webroot、共享同步目录或网络共享下；不能允许不可信主体修改其祖先。

Windows 运行者需自行确认私有 ACL 的继承与可见主体，`0700/0600` 参数不代表 Windows 权限已配置。输入原件和报告均按敏感业务资料管理，不上传第三方扫描站点，也不提交公开仓库。

由可信服务端生成不可预测任务名，不能用用户传来的标准名、租户名或 ZIP manifest 直接拼接目标。调用者创建/管理可信父目录；本程序只独占创建新任务容器，不创建任意缺失祖先。

## 正常状态

`check` 只做完整流检查，不落盘成员；它不产生后续可复用的“已信任包”。如之后调用 `extract`，对相同不可变 snapshot 再执行完整流程；不要检查一个路径再盲目读取另一版文件。

`extract` 的消费者只在 `published` 后读取 `<container>/payload/`。不要枚举 `.pending-*`，不要把容器本身存在视为成功。完整性与授权之间没有自动继承：后续索引、查询、下载仍需各自鉴权。

成功结果记录：策略版本/limits、archive SHA、任务的私有关联 ID、文件实际大小和摘要。公共演示报告只使用仓库合成数据；获准文件名仍可能敏感。重新消费前是否核对摘要由业务制定；本工具未提供不可变存储。

## 失败分类

| 结果 | 容器语义 | 操作 |
| --- | --- | --- |
| 元数据拒绝 | 本次尚未创建容器 | 保留原件于授权隔离区，联系提供者修复路径/格式/预算问题 |
| `destination_exists` | 已有对象未取得所有权，不被本次删除 | 保留原有任务，不自动改用覆盖模式；新任务选新名字 |
| 流式校验失败 | 本次新容器被尽力清理；不能消费部分文件 | 查成员号/名称摘要，仅在授权本地工具中定位；重新导出包 |
| `io_error` | 可能在保留目标/写入/发布时失败，仍尽力清理 | 检查容量/权限/完整绝对路径长度；不要将错误等同恶意样本 |
| `cleanup_failed` | 不完整容器可能残留，未发布 payload | 暂停消费，人工检查本次确切任务路径及归属后再清理；不提供广泛删除命令 |
| 进程强杀/断电、没有可靠报告 | 不承诺回滚；可能是 pending，也可能已发布但报告丢失 | 由外部任务状态/摘要核对，人工或另行设计的恢复器处理，不盲目重试相同目录 |

`issue.advice` 是静态建议，不含原始异常。CLI 输入问题折叠为 `input_or_policy_error`；授权排障时先核对文件是否普通文件、大小上限和策略数字。程序不输出私有绝对路径，操作者也不应转贴原始客户文件名。

## 修复与验证

不建议自动删除 `..`、转换大小写或去掉 link 属性后当原文件接受；这些操作会改变输入语义甚至造成碰撞。请提供者显式重命名、导出普通文件并按批准预算拆包，重新运行 check/extract。需扩大格式时先增加版本化策略和正反例，不用零/负数关闭限制。

成功后执行独立的严格 UTF-8/JSON/CSV/Markdown 解析及内容策略；解析器也必须限额和隔离。不要 eval/exec、调用 shell、渲染未净化 HTML，或直接将文本提升到模型系统指令。`looks-like-text.txt` 包裹 ZIP 的测试证明后缀不能替代内容校验。

更换 Python/zlib、策略、文件系统或部署权限后，重跑 unittest 与 demo，并检查 CI 的 skip/reparse 差异。没有真实生产吞吐和占用基准，本仓库不为多并发容量提供数字承诺。
